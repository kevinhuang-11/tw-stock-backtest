# 操作導覽

[README](../README.md) · [操作與設計細節](OPERATIONS.md) · [資料庫與 SQL](SQL.md)

這份導覽帶你用一組離線的合成資料，把工作台的主要功能走一遍，大約 5 分鐘。
過程不需要網路、不會下載行情，也不會寄信。

合成資料只用來展示軟體功能，**數值不是實際行情，不能當成策略有效的證據**。

## 最快的方式

還沒下載專案的話，照 [README 的試用步驟](../README.md#在自己的電腦上試用離線示範)執行即可。已經下載並安裝好時，在專案資料夾執行：

```bash
.venv/bin/python examples/prepare_demo.py --serve
```

這會在你自己的電腦上啟動工作台，**執行之後**才能開啟 `http://127.0.0.1:9000/watchlist`；這不是公開網站。在執行指令的終端機按 `Ctrl+C` 停止。再次執行時會沿用已建立的示例。下面兩節是同一件事分開做的方式。

## 1. 建立示例環境

在專案根目錄執行：

```bash
.venv/bin/python examples/prepare_demo.py
```

這會建立 `reports/offline-demo/`，內容包含：

- 一份獨立的設定檔與示例策略
- 三檔合成股票的行情、月營收與法人資料：9001 示範股 A（合成）、9002 示範股 B（合成）、9003 示範股 C（合成）
- 已加入這三檔的自選清單，以及第一份研究快照

這三檔不是真實的上市公司：代號不在上市普通股名單內，名稱都帶有「（合成）」，產業欄顯示為「示範產業甲／乙／丙」。名單、營收與法人的資料來源都標示為 `synthetic://offline-example`。

離線示例不提供更新。「更新自選股資料」「建立更新工作」與研究工作的連線更新在畫面上都是停用狀態，並會顯示原因；對應的指令也會拒絕執行。原因是這些功能要向官方來源查詢，而合成代號在那裡沒有資料。其餘功能（查詢、個股頁、保存快照、回測、報告預覽）都可以正常使用。

目錄已存在時指令會拒絕覆寫。想要另一份乾淨的示例，可以加上 `--output reports/offline-demo-2`，並把下一步指令中的路徑一起換掉。

## 2. 啟動工作台

```bash
.venv/bin/python -m tw_stock_backtest.cli.serve_workbench \
  --config reports/offline-demo/config.toml \
  --reports-dir reports/offline-demo/reports \
  --state-dir reports/offline-demo/workbench \
  --strategy-dir reports/offline-demo/strategies \
  --port 9000
```

開啟 `http://127.0.0.1:9000/watchlist`。工作台只監聽本機，按 Ctrl+C 結束。

同一個 state 目錄一次只能啟動一個工作台；如果 9000 埠已被先前的工作台占用，先結束它。

## 3. 自選總覽

1. 策略選「離線合成示例（非真實行情）」，按「查詢」。
2. 每一列有三個各自獨立的日期：行情日期、策略條件的評估日期、已保存研究排名的日期。它們不一定相同，畫面不會用單一「最新日期」蓋過差異。
3. 把排序改成「月增率」或「研究名次」，再切換方向。缺少數值的列固定排在最後。
4. 把狀態改成「數值不足」。示例中法人的 20 日累計只有 17 筆資料，因此顯示為不足，而不是把缺少的日子當成零。

「通過」表示符合策略條件，不代表該列的資料完整；兩者在畫面上分開呈現。

## 4. 個股頁

從自選總覽點任一檔進入個股頁。頁首有資料截至的日期、最後收盤、策略條件與研究名次，下面用分頁切換：

- **走勢與指標**：K 線、成交量、SMA／EMA／RSI／MACD。顯示範圍可以切換，但指標一律用完整歷史計算。
- **策略條件**：每個條件各自顯示通過、未通過或無法評估，並附上計算用的數值。
- **營收與法人**：目前取得的月營收與法人資料，只供研究參考，不會送入排名或回測。
- **研究歷史**、**回測**：這檔在過去研究中的名次，以及用既有引擎回測。
- **自選與筆記**：筆記只存在本機，不會出現在任何匯出的報告中。

離線示範中頁首的「更新這檔行情」是停用的；使用真實資料時，它會帶入這檔並勾選「先連線更新行情」開啟建立研究頁。

## 5. 保存與比較快照

回到自選總覽，按「保存目前策略的完整自選快照與郵件預覽」。

- 快照會固定保存當下的策略內容、數值與資料來源，之後修改策略或更新資料都不會改變它。
- 每次保存都寫入新的目錄，不覆寫先前的快照。
- 保存後會開啟結果頁，並顯示與前一份快照的比較。

比較遵守以下規則：

- 策略、股票池與指定日期都相同的快照才會比較條件變化。
- 輸入沒有改變時，比較結果就是沒有變化。同一天重複保存不算新的交易日。
- 研究名次只有在前一份的研究日期較早、且有效母體相同時才會比較。
- 第一次保存、策略不同、或前一份無法評估，會分別標示，不會算成「新通過」。

各種變化與資料修訂的情況由 [tests/test_watchlist_research.py](../tests/test_watchlist_research.py) 以合成資料驗證。

## 6. 報告輸出

在快照結果頁可以開啟：

- **郵件 HTML 預覽**與**純文字**版本：和網頁使用同一份摘要內容。預覽不需要任何憑證，也不會寄信。
- **CSV**：不包含私人筆記。

## 7. 執行測試

```bash
.venv/bin/python -m unittest discover -s tests -v
```

測試全部離線執行，涵蓋缺值處理、時間界線、資金與費稅計算。

## 改用自己的資料

如果已經依 [真實資料準備](OPERATIONS.md#真實資料準備) 下載過行情，可以沿用根目錄的 `config.toml`，另外指定空的 state 與報表目錄：

```bash
.venv/bin/python -m tw_stock_backtest.cli.serve_workbench \
  --config config.toml --reports-dir reports/demo-results \
  --state-dir reports/demo-state --strategy-dir strategies --port 9000
```

在頁面搜尋股票並加入自選即可。工作台只讀取既有資料，不會自行下載；還沒有研究排名時，該欄會顯示未提供。

## 目前的限制

- 工作台設計為單人本機使用，不適合公開部署。
- 自動化測試涵蓋到 HTTP 層；瀏覽器端的互動檢查（`tools/check_stock_picker.py`）需手動執行，不在 CI 中。
- 其他限制見 [README 的限制](../README.md#限制)。
