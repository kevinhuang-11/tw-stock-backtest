# 停牌、缺價與交易限制的處理規則

狀態：**正式規則**（2026-10-19 起；分支 `feat/halt-policy`）。第一階段的盤點與決定事項 D1～D8 已全部採用並實作。每個情況對應的測試列在 [`tests/test_halt_policy.py`](../tests/test_halt_policy.py)；測試會檢查本文件第 3 節的編號與對照表一致。

適用範圍：研究排名、篩選與條件、多股票回測、買進持有基準、單檔回測、前瞻報酬（選股評估）、策略比較、個股頁，以及這些功能產生的報表。

---

## 1. 名詞與共通原則

### 1.1 名詞

| 名詞 | 意思 |
|---|---|
| 行情日 | 行情庫中**至少一檔股票有列**的日期。專案沒有獨立的交易日曆（v1 限制）。 |
| 列 | `stock_prices` 的一筆（某股某日）。列可以有價格，也可以全部為空。 |
| 缺價 | 列存在，但開高低收為空。 |
| 缺列 | 其他股票在這個行情日有列，這檔卻沒有。 |
| 可交易 | 當日可以用開盤價成交。 |
| 估值價 | 持股的收盤估值；不可交易日沿用最近一筆有效收盤，並記錄那個價格的日期。 |

### 1.2 每個行情日的個股狀態

`data/market_events.py` 的 `market_status`：

| 狀態 | 意思 | 可交易 |
|---|---|---|
| `NORMAL` | 有價格 | 是 |
| `CONFIRMED_HALT` | 已確認停牌（清單附官方來源） | 否 |
| `NO_PRICE` | 來源有這一列，但沒有開高低收；原因未確認 | 否 |
| `MISSING_ROW` | 回測期間內缺列，且查不到公告；原因未確認，只存在記憶體中 | 否 |
| `DELISTED` | 終止上市日以後（清單附官方來源） | 否，永久 |

開始日之後才上市、以及開始日以前已終止上市的股票，不納入股票池（`universe_exclusions`），不是逐日狀態。

### 1.3 共通原則

1. **時間隔離**：任何決策（訊號、排名、委託、估值方式、說明文字）只能用當天以前已知的資訊。停牌清單的區間終點、終止上市日等資訊，只用來決定**當天**的狀態；「已公告終止上市」從公告日起才標示。
2. **不補值、不刪列**：缺價與缺列都不補價格。窗口型指標在缺價仍在窗口內時不計算，遞迴指標在缺價後重新暖機。
3. **不推定**：缺價或缺列不能自行認定為停牌或終止上市。只有查得到官方公告、附 https 來源的事件，才列入 [`confirmed_halts.json`](../src/tw_stock_backtest/data/confirmed_halts.json)。
4. **同一套規則**：研究、回測、基準、單檔回測、前瞻報酬與個股頁，對同一列得到同一個狀態。
5. **報表必須說明**：不可交易、估值沿用舊價、被排除或無法變現的，報表都列出股票、日期、狀態與原因，金額另外加總。
6. **寧可失敗，不可默默變形**：資料看起來整批沒更新、或根本沒有下載時，整次失敗並說明原因。

## 3. 逐項規則

每一項列出偵測方式與規則；「實作」列出程式位置。對應的測試見 `tests/test_halt_policy.py` 的 `CASES`。

### 3.1 已確認停牌

包含減資換發新股、變更面額、逾期申報財報、重大訊息全日暫停交易、股份轉換前的停止買賣等，只要有官方公告就屬於這一類。

- **偵測**：`confirmed_halts.json` 的 `halts`，每筆是含頭尾的日曆日區間，附原因與 https 來源。來源在停牌期間通常沒有這檔的列；`load_records` 會在區間內的行情日補上無價格、量為 0 的停牌列。
- **指標與排名**：停牌列算缺價。窗口型指標在停牌列仍在窗口內時無法評估，遞迴指標從恢復日起重新暖機。
- **委託與成交**：當日不成交，記在 `skipped_orders`（「已確認停牌，當日不成交」）。
- **估值**：沿用停牌前最後一筆有效收盤；`stale_prices` 記錄價格日期。
- **基準**：開始日就停牌的，延到第一個可交易日以開盤價買進；已持有的照常持有。
- **報表**：「停牌與無成交價日」表格列出日期、股票、狀態與原因。
- **實作**：`data/market_events.py`（`load_confirmed_halts`、`prepare_market_records`）、`data/database.py`（`load_records`）、三個引擎。

### 3.2 盤中暫停交易（部分時段）

- **規則**：不列入已確認停牌清單（清單只收全日停止買賣），當日視為 `NORMAL`，用來源的開盤價成交。開盤價可能是恢復後的第一筆成交，這是日線模擬的簡化。
- **保護**：清單上的停牌日若來源有價格，整次失敗（3.21），避免把部分時段暫停誤列為全日停牌。

### 3.3 停止買賣後終止上市（1589）

- **偵測**：停止買賣期間放在 `halts`，從停止買賣首日到終止上市前一天；終止上市放在 `delistings`，附公告日（`announced`）、終止上市日（`effective`）、類型、原因與來源。`load_delistings` 驗證：公告日不晚於終止上市日、停牌區間不可延伸到終止上市日以後。
- **終止上市日以前**：同 3.1。
- **終止上市日以後**：狀態為 `DELISTED`。來源不再有列，這不是缺列；指標不再計算，也不逐日記錄。
- **衝突**：終止上市日以後若還有行情列，整次失敗（3.21）。
- **報表**：期末持股與「無法變現」標示公告日與終止上市日；公告日晚於結束日的不標示。
- **已查證的案例**（證交所新聞稿）：1589（2026-11-18，財務）、6806（2026-06-23，財務）、2867（2026-09-01，股份轉換）、3454（2026-03-27，股份轉換）、6423（2026-01-22，轉上櫃）。

### 3.4 因合併、股份轉換、公開收購而終止上市

- **規則**：和 3.3 一樣記錄與處理，`kind` 註明類型（`share_swap`、`merger`、`tender_offer`、`transfer_to_tpex`），`consideration` 記錄公告的對價。**不模擬換股或現金入帳**；估值依 3.16 的設定，報表列出類型與對價。
- **轉上櫃**（`transfer_to_tpex`）：持有人仍可在櫃買中心交易，但本專案沒有櫃買行情，同樣列為無法變現並標示。

### 3.5 來源有該日但無價格（NO_PRICE）

- **偵測**：列存在、四個價格全部為空，且不在停牌清單；只有部分價格為空時視為資料錯誤，整次失敗。
- **規則**：與 3.1 相同，但標示為「無成交價（原因未確認，不認定為停牌）」。

### 3.6 缺列且查不到公告（4155）

- **偵測**：回測期間內，其他股票在某行情日有列、這檔沒有；不在停牌清單，也不在終止上市後。先用 `inspect_db --gaps` 找出並重新下載，排除下載缺漏。
- **規則**：只要不觸發 3.7、3.8 的整批保護，回測照常進行。這檔在缺列的行情日標為 `MISSING_ROW`：不可交易、沿用最近收盤估值，狀態文字是「缺少行情列（原因未確認，不認定為停牌）」。代表列只存在記憶體中，不寫入行情庫。
- **暖機期間**（實作時補充）：開始日以前的缺列**不補**。研究排名讀的是行情庫原本的序列，暖機期間也補的話，回測與研究的指標會不同。
- **報表**：「原因未確認的缺列」表格（股票、起訖、日數），結果的 `unconfirmed_gaps`。`run_portfolio`、`compare_strategies`、`evaluate_selection` 有缺列時退出碼為 2（結果不完整）。
- **分期比較**（實作時補充）：`compare_periods` 仍要求每檔在每段期間的起訖日都有列（不移動期間邊界），這個規則不放寬。
- **實作**：`market_events.prepare_backtest_market`、`unconfirmed_gaps`。

### 3.7 行情沒更新到分析日或回測結束日

- **回測**：某個行情日缺列的股票超過股票池的 10%，而且至少 2 檔時，判定為行情未更新完整，整次失敗。訊息列出那天、缺列檔數、例子與最後一個資料完整的行情日。常數為 `MISSING_BATCH_RATIO`、`MISSING_BATCH_MINIMUM`。
- **研究**：分析日沒有這檔的列就排除，**只看分析日當天**：
  - 其他股票當天有列：「其他股票有行情、這檔沒有列（原因未確認…）」。
  - 當天沒有任何股票有列：「行情庫在這天沒有任何股票的行情（休市日，或行情尚未更新到這天）」。不看之後的資料，所以這兩種情況不再區分（實作時補充：原本會查分析日之後的行情來分辨）。
- **實作**：`market_events.prepare_backtest_market`、`cli/screen_factors.collect_factor_rows`、`data/database.market_has_rows`。

### 3.8 股票池中有從未下載的股票

- **規則**：結束日以前沒有任何列、也不在終止上市清單的股票，整次失敗（「可能尚未下載」），不當成整段 `MISSING_ROW`。

### 3.9 期間中上市

- **規則**：行情庫旁 `listed_stocks.json` 的上市日晚於開始日的股票，不納入股票池，也不在上市後中途加入；`universe_exclusions` 與報表頁列出上市日與原因。研究不受影響。
- **實作**：`data/universe.listing_exclusions`，用於 `run_portfolio`、`compare_strategies`、`compare_periods`、`evaluate_selection`。

### 3.10 期間中下市（含倖存者偏差）

- **規則**：
  - 有終止上市紀錄的，依 3.3、3.16。
  - 終止上市日不晚於開始日的，整段期間都不能交易，不納入股票池（`listing_exclusions`）。
  - 沒有紀錄的，依 3.6。
  - 已下市的股票不在目前的上市名單裡，用名單建立股票池時不會出現（倖存者偏差，v1 限制）。

### 3.11 全市場休市（颱風假等）

- **規則**：行情日是「行情庫中至少一檔有列」的日期；全市場休市時沒有任何列，自然不是行情日，不會出現缺列。個股停牌時其他股票仍有列，所以是缺列（3.1 或 3.6）。
- **風險**：股票池很小、而且行情庫只有這幾檔時，若這幾檔同一天都缺列，會被當成休市。全市場下載時不會發生。官方休市日曆是之後的工作。

### 3.12 分析日或訊號日當天停牌

- **研究**：分析日是已確認停牌日時，排除原因是「分析日已確認停牌：（原因）」；無成交價是「分析日無成交價（原因未確認…）」；已終止上市是「已於某日終止上市（原因）」。缺列見 3.7。
- **回測訊號日**：當天不更新這檔的訊號（`errors`）。已持有的保留並占持股名額（凍結），但已決定賣出的不凍結（3.15）；未持有的不會被選入。

### 3.13 停牌跨過回測開始日

- **策略**：開始日時沒有持股；在可交易且指標可評估以前不會被選入。
- **基準**：延到第一個可交易日，以開盤價和開始日就固定的預算買進。整段期間都不可交易的，預算維持現金，報表頁的「基準未買進的股票」列出（`unavailable_entire_period`，以及預算不足的 `unbought`）。

### 3.14 停牌跨過回測結束日（期末估值）

- **規則**：期末不強制賣出。停牌、無成交價、缺列的持股以最近有效收盤估值。
- **報表**：「期末持股」（`final_positions`）列出股數、估值價、價格日期、金額與狀態；結束日以前已公告終止上市的（公告日不晚於結束日），另外標示公告日與終止上市日。策略列出全部持股，基準只列出不是正常狀態的持股。CLI 的期末持股與基準持股同樣附上狀態。
- **實作**：`backtesting/positions.final_positions`。

### 3.15 持股停牌時的賣出決定

- **規則**：
  - 訊號日決定賣出、成交日卻不可交易時，保留「賣出意圖」（`sell_intents`）。之後每天都重新計畫賣出，在第一個可交易的開盤賣出，不論那天指標能不能評估。成交紀錄的 `intent_date` 是最初決定賣出的訊號日。
  - 停牌期間仍占持股名額，現金不會釋出。
  - 重新評估後又進入目標持股的，取消賣出意圖（實作時補充）。
  - 恢復後沒有賣出意圖、但指標仍在暖機的持股，維持持有（沒有訊號就不動作）。
- **實作**：`backtesting/portfolio.py`。

### 3.16 持有到終止上市

- **規則**：
  - 終止上市日開盤前，持股移到「無法變現」（`unrealizable`）：不再占持股名額，金額計入總資產但不是現金、不能用來買進。
  - 估值依 `[halts] delisted_valuation`：`last_close`（預設，以最後一筆有效收盤凍結）或 `zero`（壓力測試，從終止上市日起為 0）。
  - 資產曲線每天記錄 `unrealizable_value`；結果記錄 `delisting_events` 與 `delisted_valuation`。
  - 基準套用相同規則；前瞻報酬的出場日已終止上市時，依同一個設定（3.22）。
- **單檔回測**（實作時補充）：單檔引擎只有這檔自己的行情，沒有行情日可判斷終止上市，序列在最後一列結束，不另外處理。
- **實作**：`backtesting/delisting.py`。

### 3.17 處置股（分盤集合競價）

- **規則**：只偵測並標示，不模擬交易限制。處置期間仍可交易，回測照常以開盤價成交。
  - 標示的位置：回測的成交與期末持股（含策略比較的子報表），以及研究排名。
  - 處置在公布日以後、處置起迄日之間才標示。
  - 處置期間遇停止買賣或全日暫停交易會順延，這裡只用公告的起迄日，不推算順延。
- **資料**：`fetch_restrictions` 下載證交所「公布處置有價證券」（每個日曆年一次查詢），只保留四位數代號，存在 `trading_restrictions`（schema 遷移 5）。
- **報表**：寫明已下載的範圍；沒下載過的期間不能當成「沒有限制」。注意股不標示。

### 3.18 全額交割股（變更交易方法）

- **規則**：同 3.17，只標示「變更交易方法（全額交割）」，分盤集合競價另外註明，不模擬預收款券。
- **資料**：證交所「變更交易」名單（TWT85U）只提供某一天的名單，所以逐日下載本機行情庫有行情的日子。讀取時，同一檔在連續下載過的日子都在名單上，就合併成一段期間。
- **注意**：停止買賣期間通常不在名單上（例如 2321 減資停牌時），停止買賣仍以停牌清單為準。

### 3.19 漲跌停鎖死

- **規則**：不在本次範圍，維持「以開盤價成交」的簡化（已知限制）；開盤即漲停或跌停時，回測仍會成交。

### 3.20 停牌期間或恢復日的公司行動

- **規則**：公司行動照生效日處理。減資與變更面額在恢復買賣日開盤前換股，停牌期間以舊股數、停止前收盤估值。生效日剛好在停牌中的除權息，照常在生效日入帳。

### 3.21 停牌清單與來源資料衝突

- **規則**：以下情況整次失敗，人工檢查清單或資料：
  - 清單上的停牌日，來源有那天的價格。
  - 終止上市日以後，來源還有行情列。
  - `load_records` 補停牌列時不覆寫來源既有的列。

### 3.22 前瞻報酬的進場日或出場日不可交易

- **進場日不可交易**：無法評估（不延後進場，否則樣本會偏向可交易的日子）。
- **出場日不可交易**：
  - 以最近一筆有效收盤估值，標示 `stale_exit`、價格日期與狀態，和回測的持股估值一致；摘要另外計數。
  - 出場日已終止上市的，依 `delisted_valuation`。
  - 出場日之前從未有收盤價的，無法評估。
- **選股評估的既有規則**：任何一檔在訊號日無法評估時，當天的比較作廢（`ranking_incomplete`），這個規則不變。所以全市場時幾乎每天都作廢（見第 6 節）。
- **實作**：`analysis/forward_returns.py`、`cli/evaluate_selection.py`。

### 3.23 單檔回測：訊號遇到不可交易日

- **規則**：賣出訊號遇到不可交易日時保留，在下一個可交易日開盤賣出（`intent_date` 記錄原訊號日）；買進訊號遇到不可交易日則作廢，因為買進的理由可能已經過時。
- **實作**：`backtesting/backtest.py`。

### 3.24 暖機期間（回測開始日前）的停牌與缺價

- **規則**：只影響指標能不能計算，不讓回測失敗；暖機期間的已確認停牌也會補停牌列，缺列不補（3.6）。

## 6. 已知限制

- 沒有獨立交易日曆，行情日由行情庫推得（3.11）。
- 倖存者偏差：已下市的股票不在名單內（3.10）。
- 盤中暫停交易、漲跌停鎖死、處置的分盤撮合與全額交割的預收款券都不模擬（3.2、3.17～3.19）。
- 合併、收購類終止上市的對價不模擬入帳（3.4）。
- 處置期間的順延不推算（3.17）。
- 選股評估在任何一檔無法評估的日子作廢比較，全市場時幾乎沒有有效樣本（3.22）。
- 個股頁以清單列出不可交易的日子，圖上不另外標示。
