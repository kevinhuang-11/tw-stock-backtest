# 停牌、缺價與交易限制的處理規則

狀態：**第一階段草案**（2026-10-19）。本文件盤點所有情況、訂出規則，並對照目前程式的行為。第 5 節的決定事項確認後，第二階段一次補齊缺口，屆時把本文件改為正式規則，並刪除「目前行為」的差異標記。

適用範圍：研究排名、篩選與條件、多股票回測、買進持有基準、單檔回測、前瞻報酬（選股評估）、個股頁圖表，以及這些功能產生的報表。

## 1. 名詞與共通原則

### 1.1 名詞

| 名詞 | 意思 |
|---|---|
| 行情日 | 行情庫中**至少一檔股票有列**的日期。專案沒有獨立的交易日曆（v1 限制）。 |
| 列 | `stock_prices` 的一筆（某股某日）。列可以有價格，也可以全部為空。 |
| 缺價 | 列存在，但開高低收為空。 |
| 缺列 | 其他股票在這個行情日有列，這檔卻沒有。 |
| 可交易 | 當日可以用開盤價成交。 |
| 估值價 | 持股的收盤估值；不可交易日沿用最近一筆有效收盤，並記錄那個價格的日期。 |

### 1.2 每個行情日的個股狀態

目前程式有前三種狀態（`data/market_events.py` 的 `market_status`）；後三種是本文件提議新增的。

| 狀態 | 意思 | 可交易 | 目前 |
|---|---|---|---|
| `NORMAL` | 有價格 | 是 | 已有 |
| `CONFIRMED_HALT` | 已確認停牌（清單附官方來源） | 否 | 已有 |
| `NO_PRICE` | 來源有這一列，但沒有開高低收；原因未確認 | 否 | 已有 |
| `MISSING_ROW` | 缺列且查不到公告；原因未確認 | 否 | **新增**（見決定事項 D2） |
| `DELISTED` | 已終止上市（清單附官方來源） | 否，永久 | **新增**（見 D1、D7） |
| `NOT_LISTED` | 回測開始日之後才上市 | 不在股票池 | 已有，但以排除處理，不是逐日狀態 |

### 1.3 共通原則

1. **時間隔離**：任何決策（訊號、排名、委託、估值方式）只能用當天以前已知的資訊。停牌清單的區間終點、終止上市日等「未來資訊」只能用來決定**當天**的狀態，不能用來提前行動。
2. **不補值、不刪列**：缺價與缺列都不補價格，也不從序列中刪除；窗口型指標在缺價仍在窗口內時不計算，遞迴指標在缺價後重新暖機（已實作，見 CLAUDE.md「缺價的處理」）。
3. **不推定**：缺價或缺列不能自行認定為停牌。只有查得到官方公告、附 https 來源的事件，才能標成停牌或終止上市。
4. **同一套規則**：研究、回測、基準、單檔回測、前瞻報酬與個股圖，對同一列要得到同一個狀態，並用同樣的方式顯示。
5. **報表必須說明**：凡是不可交易、估值沿用舊價、被排除或無法變現的，報表都要列出股票、日期、狀態與原因，金額另外加總。
6. **寧可失敗，不可默默變形**：資料看起來整批沒更新、或根本沒有下載時，整次失敗並說明原因，不把大範圍缺漏當成個股狀態處理。

## 3. 逐項規則

每一項依序列出：偵測、指標與排名、委託與成交、持股估值、買進持有基準、報表、偷看未來的風險，最後是目前的行為（附檔案與測試）。

### 3.1 已確認停牌

包含減資換發新股、變更面額、逾期申報財報、重大訊息全日暫停交易、處置期間轉為停止買賣等，只要有官方公告就屬於這一類。

- **偵測**：`src/tw_stock_backtest/data/confirmed_halts.json`，每筆是含頭尾的日曆日區間，附原因與 https 來源。來源在停牌期間通常沒有這檔的列；`load_records` 會在區間內的行情日補上無價格、量為 0 的停牌列。
- **指標與排名**：停牌列算缺價。窗口型指標在停牌列仍在窗口內時無法評估，遞迴指標從恢復日起重新暖機。研究排名把這檔列為無法評估，並寫出原因。
- **委託與成交**：當日不成交；委託記在 `skipped_orders`，原因是「已確認停牌，當日不成交」。
- **估值**：沿用停牌前最後一筆有效收盤，`stale_prices` 記錄價格日期。
- **基準**：開始日就停牌的，延到第一個可交易日以開盤價買進；已持有的照常持有，估值同上。
- **報表**：「停牌與無成交價日」表格列出日期、股票、狀態與原因（來源在清單中）。
- **偷看未來**：每天只看當天狀態，不使用區間的終點。✅
- **目前**：✅
  - 程式：`data/market_events.py`（`load_confirmed_halts`、`prepare_market_records`）、`data/database.py`（`load_records`）、`backtesting/portfolio.py`、`backtesting/benchmark.py`、`backtesting/backtest.py`。
  - 測試：`test_confirmed_halts.py`（`test_confirmed_halt_days_get_halt_rows_without_prices`、`test_backtest_runs_through_the_halt_instead_of_failing`）、`test_halt_continuation.py`（全部）、`test_market_events.py`（`test_halt_keeps_raw_prices_and_does_not_modify_input`、`test_future_price_is_not_used_for_halt_valuation`）、`test_missing_prices.py`（`test_confirmed_halt_stays_in_the_window_like_research_ranking`）。

### 3.2 盤中暫停交易（部分時段）

重大訊息常在盤中暫停，之後同日恢復。來源當天有成交，有開高低收。

- **規則**：不列入已確認停牌清單，當日視為 `NORMAL`，用來源的開盤價成交。開盤價可能是恢復後的第一筆成交，這是日線模擬的簡化，在限制中說明。
- **偵測**：之後若下載暫停交易公告，只在報表標示「盤中曾暫停交易」，不改變成交。
- **偷看未來**：無。
- **目前**：⚠️ 沒有區分全日與部分時段。若有人把部分時段暫停加進停牌清單，而來源當天有價格，會因「行情與已確認停牌事件不一致」整次失敗（`test_market_events.py` 的 `test_conflicting_event_and_prices_are_rejected`）。這個失敗本身是正確的保護；缺的是文件說明：清單只收全日停止買賣。

### 3.3 停止買賣後終止上市（1589）

- **偵測**：停止買賣區間放在停牌清單，從停止買賣首日到終止上市前一天。終止上市日另外記錄（提議新增，見 D7），附公告日與來源。
- **終止上市日以前**：同 3.1。
- **終止上市日以後**：狀態為 `DELISTED`。來源不再有列，這不是缺列，也不能讓回測失敗。指標不再計算，不會出現在排名中。
- **委託與成交**：不可交易；不能委託買進。持股的處理見 3.16。
- **報表**：「終止上市」表格列出公告日、終止上市日、原因與來源。
- **偷看未來**：「已公告終止上市」只能從**公告日**起標示。例如 1589 在 2026-10-08 公告，在這天之前的報表不能出現「將終止上市」。
- **目前**：⚠️
  - 停止買賣區間已在清單（c84dbf0），回測結束日在 11-17 以前時可以正確處理。
  - 結束日跨過 11-18 時，因為缺列而整次失敗。
  - 沒有終止上市的資料，也沒有 `DELISTED` 狀態。

### 3.4 因合併、股份轉換、公開收購而終止上市

持有人會收到現金或存續公司的股票（對價已公告），和 1589 這種「股票可能一文不值」的情況不同。

- **規則（v1）**：和 3.3 一樣記錄與標示，`kind` 註明是合併、股份轉換或收購，報表列出公告的對價，但**不模擬換股或現金入帳**。估值依 3.16 的設定。之後可以把對價當成一種公司行動處理。
- **目前**：❌ 沒有資料，也沒有處理。2026-08～10 的股票池中目前沒有這種情況。

### 3.5 來源有該日但無價格（NO_PRICE）

例如只有零星的零股成交，整股沒有成交價。

- **偵測**：列存在，四個價格全部為空，且不在停牌清單。只有部分價格為空時視為資料錯誤，整次失敗。
- **指標、委託、估值、基準、報表**：和 3.1 相同，但狀態標為「無成交價（原因未確認，不認定為停牌）」。
- **偷看未來**：無。
- **目前**：✅
  - 程式：`data/market_events.py`。
  - 測試：`test_market_events.py`（`test_unconfirmed_missing_prices_are_no_price_not_halt`、`test_partially_missing_prices_are_rejected`）、`test_missing_prices.py`（`test_unconfirmed_unpriced_day_inside_the_period_is_not_tradable_and_reported`、`test_engine_does_not_trade_on_a_no_price_day_and_says_why`、`test_engine_values_a_held_position_at_the_last_close_on_a_no_price_day`）。

### 3.6 缺列且查不到公告（4155）

- **偵測**：其他股票在某行情日有列，這檔沒有；不在停牌清單，也沒有終止上市紀錄。先用 `inspect_db --gaps` 找出，重新下載確認不是下載缺漏。
- **規則（依 D2 的建議）**：
  - 只要不觸發 3.7、3.8 的整批保護，回測照常進行。這檔在缺列的行情日標為 `MISSING_ROW`，視為不可交易，沿用最近收盤估值。
  - 狀態文字是「缺少行情列（原因未確認，不認定為停牌）」，和 `NO_PRICE` 分開統計。
- **指標與排名**：缺列的日子在記憶體中以無價格列代表（不寫入行情庫），所以窗口規則和缺價相同。研究在分析日缺列時，這檔列為無法評估。
- **委託與成交、估值、基準**：和 3.5 相同。
- **報表**：
  - 單獨列出「原因未確認的缺列」：股票、起訖日與日數。
  - 結果狀態標為「含未確認缺漏」，CLI 退出碼 2（沿用研究類 CLI 的約定）。
- **偷看未來**：判斷某天是否為行情日，只用當天有沒有其他股票的列，不需要未來資料。
- **目前**：⚠️ 整次回測失敗，訊息列出最早缺的日期（`market_events.prepare_backtest_market`）。全市場回測只能手動排除 4155。
  - 測試：`test_missing_prices.py`（`test_missing_row_still_fails_with_a_specific_message`）、`test_portfolio_backtest.py`（`test_missing_daily_record_is_rejected`）、`test_benchmark.py`（`test_missing_date_is_rejected`）。
  - 篩選歷史（`analysis/screening_history.py`）不會整次失敗，只把那一檔當天列為錯誤（`test_screening_history.py` 的 `test_missing_date_is_reported`）。兩者行為不一致。

### 3.7 行情沒更新到分析日或回測結束日

和 3.6 的差別：這是**很多股票同時**少了最近幾天，通常是只更新了一部分股票。

- **偵測**：某行情日缺列的股票，超過股票池的 10%，而且至少 2 檔（比例見 D2）。
- **規則**：
  - 回測與選股評估：整次失敗，訊息列出那天、缺列檔數與建議（更新行情，或把結束日提前到資料完整的最後一天）。不把它當成 `MISSING_ROW`。
  - 研究：沿用目前的「同日新鮮度檢查」，分析日沒有這檔的列就排除並說明。自動分析日取股票池中最新的日期。
- **報表**：資料狀態頁列出每檔落後幾個行情日（已實作）。
- **偷看未來**：研究目前在分析日沒有這檔列時，會查分析日**之後**是否還有這檔的行情，用來分辨「休市或未交易」與「未更新」（`cli/screen_factors.collect_factor_rows` 呼叫 `next_record_date`）。這只影響說明文字、不影響名次，但同一份報表日後重跑，說明可能不同。改為只看分析日當天其他股票有沒有列：有就是「這檔缺列（原因未確認）」，都沒有就是「休市日」。
- **目前**：⚠️ 研究正確排除；回測和 3.6 一樣以單檔訊息失敗，沒有說明是整批未更新。
  - 測試：`test_research.py`（`test_missing_close_and_stale_are_reported`、`test_automatic_latest_date_requires_each_stock_freshness`）、`test_screen_factors_cli.py`（`test_stale_stock_does_not_block_next`、`test_weekend_is_not_reported_as_stale_data`、`test_date_after_latest_data_is_still_stale`）、`test_data_status.py`（`test_lag_counts_later_local_trading_days`）。

### 3.8 股票池中有從未下載的股票

- **偵測**：回測期間內與暖機期間都沒有任何列，不在停牌清單，上市日也不晚於開始日。
- **規則**：整次失敗，訊息是「尚未下載行情」，列出股票。不當成 `MISSING_ROW`，否則整段期間都會默默不可交易。
- **目前**：⚠️ 以 3.6 的缺列訊息失敗，沒有說明是從未下載。

### 3.9 期間中上市

- **偵測**：行情庫旁 `listed_stocks.json` 的上市日晚於回測開始日。
- **規則**：不納入股票池，也不在上市後中途加入；報表的「未納入股票池」列出上市日與原因（上一個分支已定案）。研究不受影響：分析日已上市的照常排名，上市不久的因窗口不足而無法評估。
- **偷看未來**：上市日在開始日以後，排除不使用任何價格資訊。✅
- **目前**：⚠️
  - `run_portfolio`、`compare_strategies`、`compare_periods` 已排除（`data/universe.listing_exclusions`；測試 `test_listing_universe.py` 全部）。
  - 選股評估（`cli/evaluate_selection.py`）沒有排除，遇到新上市股票仍會因缺列失敗。

### 3.10 期間中下市（含倖存者偏差）

- **偵測**：
  - 已下市的股票不在目前的上市名單裡，用名單建立股票池時根本不會出現（倖存者偏差，v1 限制）。
  - 若使用者用 `--stocks` 指定已下市的股票，終止上市日以後沒有列。
- **規則**：
  - 有終止上市紀錄的（D7），依 3.3、3.16 處理。
  - 沒有紀錄的，依 3.6（缺列、原因未確認）。
  - 倖存者偏差維持在已知限制中說明。修正需要歷史名單與已下市股票的行情，不在本次範圍。
- **目前**：❌

### 3.11 全市場休市（颱風假等）

- **偵測**：行情日的定義是「行情庫中至少一檔有列」。全市場休市時沒有任何股票有列，自然不是行情日，不會出現缺列，也不會被當成停牌。
- **和個股停牌的區分**：個股停牌時其他股票仍有列，所以是缺列（3.1 或 3.6），不是休市。
- **風險**：股票池很小、而且行情庫只下載了這幾檔時，如果這幾檔都停牌，那天會被誤當成休市。全市場下載時不會發生。
- **規則**：維持目前的定義。`inspect_db --gaps` 列出相鄰兩筆間隔過長、且全庫都沒有列的區段，供人工確認。官方休市日曆是之後的工作（v1 限制：沒有交易日曆）。
- **目前**：✅
  - 程式：`market_events.prepare_backtest_market`（行情日取所有股票日期的聯集）、`data_status.price_gaps`。
  - 測試：`test_data_quality_sql.py`（`test_market_lag_for_every_kind_of_day`、`test_gaps_with_lag_window_function`）、`test_screen_factors_cli.py`（`test_weekend_is_not_reported_as_stale_data`）。

### 3.12 分析日或訊號日當天停牌

- **研究**：分析日是停牌日時，`load_records` 補了停牌列，這檔因窗口內有缺價而無法評估。原因應寫成「分析日已確認停牌（原因：…）」，而不是一般的缺價說明。`NO_PRICE` 與 `MISSING_ROW` 也各自寫出狀態。
- **回測訊號日**：當天不更新這檔的訊號（`errors` 記錄原因）。已持有的保留並占持股名額（凍結）；未持有的不會被選入。
- **偷看未來**：無。
- **目前**：⚠️ 回測正確。研究的排除原因是窗口缺價的通用訊息，沒有說是停牌（`test_missing_prices.py` 的 `test_gap_on_the_analysis_date_needs_a_full_window`）。

### 3.13 停牌跨過回測開始日

- **策略**：開始日時沒有持股；這檔在可交易且指標可評估以前不會被選入。
- **基準**：延到第一個可交易日，以開盤價、原本保留的預算買進；整段期間都不可交易的，預算維持現金，並列在「整段期間皆無法交易而未買進」。
- **偷看未來**：預算在開始日就依股票數固定，不依之後誰能交易調整。✅
- **目前**：✅（`test_halt_continuation.py` 的 `test_benchmark_delays_only_the_halted_stock`、`test_benchmark.py` 的 `test_delayed_buy_uses_resumption_open`）。
  - 缺口：報表頁沒有列出基準的「未買進」與「整段期間無法交易」，只有 CLI 會印出（見 3.14）。

### 3.14 停牌跨過回測結束日（期末估值）

- **規則**：
  - 期末不強制賣出（現有原則）。停牌中的持股以停牌前收盤估值。
  - 報表新增「期末持股」表格，標示「停牌中，估值為 YYYY-MM-DD 收盤」並另列金額。
  - 若結束日時已公告終止上市（公告日不晚於結束日），改標「已公告終止上市」，估值依 3.16 的設定。
- **偷看未來**：只用結束日以前的公告。
- **目前**：⚠️ 估值正確，但 `stale_prices` 只存在 `results.json` 的資產曲線裡，CLI 與報表頁都沒有顯示；報表頁也沒有期末持股、基準未買進與整段無法交易的清單。

### 3.15 持股停牌期間出現賣出訊號，以及恢復後的暖機期間

情境：訊號日決定賣出持股 A，成交日 A 停牌。

- **規則（依 D4 的建議）**：
  - 賣出意圖保留為「待賣出」。之後每個 A 可交易的開盤都重試，不論那天 A 的指標能不能評估。
  - A 停牌期間仍占持股名額，現金不會釋出（現有規則）。
  - 恢復後若沒有待賣出，而指標仍在暖機：維持持有。沒有訊號就不動作，報表列出原因。
- **偷看未來**：重試只依當天可不可交易決定。✅
- **目前**：⚠️ 不一致。賣出失敗後不保留意圖：
  - 停牌期間 A 被凍結；恢復後窗口內仍有停牌列，指標無法評估，又被凍結到窗口清空才會重新評估、賣出。
  - 用合成資料驗證（窗口 5～6 筆、停牌 3 天）：03-27 的訊號已決定賣出，04-02 恢復買賣，到 04-10 才賣出，晚了 6 個行情日。實際策略的窗口是 20 日，延遲會更長。
  - 程式：`backtesting/portfolio.py`（`frozen` 與 `plan_rebalance`）。
  - 測試：`test_portfolio_backtest.py` 的 `test_halted_sell_does_not_release_slot_or_cash`、`test_halt_continuation.py` 的 `test_failed_sell_does_not_release_cash` 與 `test_halted_holding_still_uses_position_slot` 只驗證停牌期間，沒有涵蓋恢復後的暖機期。

### 3.16 持有到終止上市

- **基準**：相同規則。
- **偷看未來**：估值改變只從終止上市日起（`zero`），標示只從公告日起，不能提前。

## 5. 需要決定的事項

### D1 持有到終止上市

你的傾向：預設以最後收盤價凍結估值，報表標示「無法變現」並另列金額；另提供設定以零估值做壓力測試。

**建議：同意，並補三點：**

1. **終止上市後不再占持股名額，但金額不能動用。** 停牌中的持股仍占名額，因為可能恢復買賣；終止上市是永久的，占著名額會讓策略之後的回測一直少一檔。資金被卡住的效果，已經由「這筆錢不能用來買進」表現出來。
2. **標示從公告日開始，估值改變從終止上市日開始。** `zero` 設定從終止上市日起估值為 0，不提前，避免偷看未來。
3. **合併、收購類的終止上市只標示對價，不模擬入帳。** 這類情況持有人會收到對價，用 `zero` 壓力測試並不合理；報表要寫清楚。

### D2 缺列且查不到公告

你的傾向：不手動排除；回測照常進行，該股在缺漏期間視為不可交易、沿用最近收盤估值，報表標示「原因未確認」。

**建議：同意，但要加上整批保護，並明確標示這次回測不完整：**

1. **新狀態 `MISSING_ROW`**，和 `NO_PRICE` 分開。兩者的成因不同，一個是來源有列但沒價格，一個是來源連列都沒有。
2. **整批保護（仍然整次失敗）**：
   - 某行情日缺列的股票超過股票池的 10%，而且至少 2 檔時，判定為行情未更新完整（3.7）。
   - 期間與暖機期間都沒有任何列的股票，判定為尚未下載（3.8）。

   沒有這兩道保護，只更新了一半的行情庫也會「成功」跑完，數百檔股票的最後幾天被默默當成不可交易。這違反「寧可失敗，不可默默變形」。10% 與 2 檔是建議值；4155 這種單檔情況不會觸發。
3. **標示結果不完整**：報表與 CLI 列出每一檔的缺列區間與日數，結果狀態是「含未確認缺漏」，`run_portfolio` 的退出碼改為 2，沿用研究類 CLI「允許部分且仍有有效結果」的約定。
4. **不寫入行情庫**：缺列只在記憶體中以無價格列代表，`inspect_db --gaps` 仍然看得到原本的缺口。

### D3 處置股與全額交割

你的傾向：這次只偵測並在報表標示，不模擬交易限制。

**建議：同意。** 補充：

- 偵測需要新的下載（處置公告、變更交易方法公告）與新的資料表（schema 遷移 5），有請求上限、失敗時整批不寫入，和公司行動相同。
- 第一次下載範圍限 2026 年；請求數會在 `--plan` 中列出，下載前另外確認。
- 注意股只是提醒，不標示。

### D4 停牌期間的賣出意圖（新增）

**建議：保留賣出意圖，在第一個可交易的開盤重試，不論那天指標能不能評估。** 實際交易中，決定賣出的股票恢復買賣後會直接賣；目前的行為會讓它多持有一整個指標窗口（20 個行情日）。這只用到當天可不可交易，沒有偷看未來的風險。

另外，恢復後沒有待賣出、但指標仍在暖機的持股，維持目前的做法（續抱）：沒有訊號就不動作。

### D5 單檔引擎的訊號重試（新增）

**建議：賣出訊號保留到下一個可交易日；買進訊號作廢。** 理由同 D4。買進的理由可能已經過時，而且多股票引擎的買進是每天重新規劃的，這樣兩個引擎的結果方向一致。

### D6 前瞻報酬的出場日不可交易（新增）

**建議：改為以最近收盤估值並標示 `stale_exit`、另外計數；進場日不可交易維持無法評估。** 理由見 3.22：目前的做法會讓停牌（常是壞消息）的樣本消失、高估報酬，而且全市場時股票池的比較會大量作廢。改了之後和回測的估值方式一致。這會改變既有選股評估的數字，報表要註明規則版本。

### D7 終止上市資料放在哪裡（新增）

**建議：放在同一個 `confirmed_halts.json`，schema 升為 2，新增 `delistings` 陣列。** 每筆包含股票、公告日、終止上市日、類型（財務、合併、股份轉換、收購、其他）、原因、對價（如有）與 https 來源。

理由：

- 和停牌清單的審核規則相同（只收查得到官方公告的，附來源），放在一起方便一起檢查。
- 目前只有個位數的案例，人工維護即可。
- 之後如果要修正倖存者偏差，再改成從證交所的終止上市清單下載。

舊的 schema 1 檔案仍可讀取。

### D8 期末估值與期末持股的報表（新增，較小）

**建議：報表頁與 CLI 都加上「期末持股」**，列出股票、股數、估值價、價格日期與狀態（正常、停牌中、無法變現），並列出基準的「未買進」與「整段期間無法交易」。這只是顯示，不改變數字。
